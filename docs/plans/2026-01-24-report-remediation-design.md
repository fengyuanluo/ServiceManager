# 审阅问题修复设计

**目标**：按 report.md 顺序逐项高质量修复，保证安全、稳定性与交互闭环，并保持测试通过。

**范围**：后端启动/配置/认证/中间件/服务管理核心/构建脚本；前端接口容错与关键交互缺口。

## 修复策略
- 按 report.md 顺序推进，保证依赖顺序与回归路径清晰。
- 采用“最小可行变更 + 明确边界 + 可验证”原则，避免引入非必要重构。
- 错误处理统一语义：输入错误(400)、认证失败(401)、管理器不可用(400/503 视约定)、内部异常(500)。

## 任务顺序与核心变更
1. 启动与配置链路：补齐 `cmd/start.go` 错误处理与初始化顺序；修正 `internal/conf/config.go` 配置键与映射；日志级别读取配置。
2. 认证与用户：默认账号策略调整；JWT 签名算法校验与密钥治理；Auth 中间件严格处理 Bearer 并返回 401。
3. 中间件：CORS 与 credentials 合法配置；静态资源中间件关闭文件句柄，缺失文件走 `Next()`/SPA fallback。
4. 服务管理核心：PM2 调用避免命令拼接；服务名校验防路径穿越与配置注入。
5. 构建与发布：`scripts/build.sh` 的 LDFLAGS/APP_NAME 统一；`scripts/dockerfile/entrypoint.sh` 启动命令纠偏。
6. 前端：ServiceEditor 保存/重置闭环或显式禁用；CreateWizard 步骤逻辑补齐；API client 兼容空响应/非 JSON；标记或移除 mock 数据。

## 测试与验证
- 基线：`go test ./...`、`pnpm -C web test`。
- 逐项修复后按模块回归：后端接口单元测试 + 前端关键交互测试。
- 关键验证点：认证与权限、静态资源路由、服务管理命令执行安全、构建产物一致性。

## 风险与对策
- 安全变更影响登录与 token：通过测试与手动 smoke 验证覆盖。
- 构建脚本调整影响发布：与现有发布产物命名一致性对齐。
