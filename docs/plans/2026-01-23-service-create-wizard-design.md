# 服务新增向导设计

## 目标
在当前管理器页内提供新增服务向导（悬浮对话框），与批量操作同一行入口，支持表单与原始文本切换，创建成功后自动刷新并定位新服务。

## 约束
- Vue3 + Vite + Tailwind（纯静态构建）。
- 中英双语，文字极简。
- 不额外选择管理器，使用当前 managerKey。
- 响应式（移动/桌面），悬浮对话框非右侧抽屉。

## 方案对比

### 方案 A：右侧抽屉式向导
优点：空间充足，信息密集展示方便。
缺点：用户明确要求不使用抽屉；移动端体验拥挤。

### 方案 B：居中悬浮对话框（推荐）
优点：聚焦、干净、操作路径短；移动端可自动铺满宽度；与现有“卡片”风格一致。
缺点：可展示信息有限，需要分步组织。

### 方案 C：全屏覆盖向导
优点：步骤清晰，适合复杂流程。
缺点：视觉侵入感强，打断当前上下文。

推荐结论：采用方案 B，契合“精致极简 + 悬浮对话框”要求。

## 信息结构与交互
1. 模板选择：展示当前管理器可创建的模板但无需切换管理器，仅作为提示或预填。
2. 表单输入：名称、描述、执行命令、工作目录、用户、环境变量；可切换原始文本。
3. 确认创建：摘要与提交按钮，提交中显示细节状态。

## 组件与数据流
- 新增组件 ServiceCreateWizard.vue：内部维护步骤、表单状态与 raw 文本。
- BatchToolbar.vue 增加“新增”按钮（与批量按钮同行）。
- ManagerPanel.vue 负责打开/关闭向导，并在创建成功后调用 listServices 刷新并选中新服务。
- api/services.ts 添加 createService，请求 /api/v1/{manager}/create。

## 测试策略
- 前端：向导打开、提交流程、API 请求参数校验（Vitest）。
- 后端：已具备创建逻辑，复用现有测试。

## 风险与降级
- 无 Context7 文档支持时，遵循 Vue 3 基础可访问性模式（遮罩、ESC 关闭、聚焦转移）。
