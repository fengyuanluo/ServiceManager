# 安装提示/缺失检测 UI 设计

## 目标
为各服务管理器页面增加“缺失检测 + 安装提示 + 确认安装”的轻量交互，满足“先检测、明显提示、用户确认后安装”的要求，并保持极简、优雅的视觉风格与中英双语一致性。

## 方案对比
- 方案 A：列表区内嵌提醒卡片（推荐）
  - 优点：与“列表快加载”逻辑一致，用户第一眼可见；改动范围小、实现快；不干扰详情区布局。
  - 缺点：卡片占用列表空间。
- 方案 B：详情区空态替换为安装引导
  - 优点：集中提示更完整。
  - 缺点：列表与批量操作仍显示空态，用户可能误解为“暂无服务”。
- 方案 C：全局顶部提示条
  - 优点：提示强、醒目。
  - 缺点：影响所有页面视觉，违背“文字少且精炼”的审美要求。

## 推荐方案
采用方案 A：在列表卡片顶部插入一张明显但克制的提示卡片，使用暖色边框与柔和背景突出“缺失”状态，提供单一“安装”按钮。安装过程以最小文字反馈（安装中/已安装/失败）。确认动作使用浏览器原生确认对话框，避免引入复杂模态组件。

## 交互流程
1. 调用列表接口失败且错误为“manager unavailable” → 进入 missing 状态。
2. missing 状态展示提示卡片；“安装”按钮需二次确认。
3. 用户确认后调用 `/install`；按钮显示“安装中”。
4. 成功后刷新列表并清理缺失状态；失败则展示失败提示并允许重试。

## 视觉与文案
- 提示卡片采用圆角、半透明背景、细边框，保持与现有卡片一致。
- 文案使用大写细字距标签（与现有 UI 统一），中英双语映射。
- 文案极简：缺失、安装、安装中、已安装、失败。

## 测试策略
- ManagerPanel 单测：列表接口报错时出现提示卡片。
- 点击安装按钮时触发 `installManager`；确认取消不触发。
